# 方法库记忆

把本地那套 RAG（四个语料库 + 时间衰减 + 卡片优先）接进 Harness，做成两个能力。

## 它做什么

1. **步骤开始前自动检索**。每次模型要处理一条新的用户消息时，用这条消息去查方法库，把命中的经验块作为一条额外消息插到上下文里，包在 `<preflight>` 标签中。没有命中就什么都不插。
2. **`rag_search` 工具**。模型可以自己换一种说法再查一次，指定条数与语料库，拿到带分数的命中列表。

两者查的是同一份索引，配置在同一个地方。

## 语料库

| 库 | 内容 |
| --- | --- |
| `code` | 开源协作规范、报错避坑、语法与工具链坑 |
| `finance` | 量化因子、平台规则、回测与风控经验 |
| `task` | 任务进度、环境快照、交接状态 |
| `life` | 日记与日常 |

默认查前三个；问的是日记、聊天、日常生活时才会加上 `life`。

## 配置

写在 `cordis.patch.yml` 的 `config` 下，通常只需要动这几个：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `python` | 本机 Python 3.13 | 用来跑检索脚本的解释器 |
| `script` | `…\rag\preflight.py` | 检索入口 |
| `cwd` | `…\rag` | 工作目录，索引相对它解析 |
| `inject` | `true` | 关掉就不再自动注入，只留工具 |
| `k` | `3` | 自动注入取几条 |
| `tool` | `true` | 关掉就不注册 `rag_search` |
| `toolK` | `4` | 工具默认取几条 |
| `maxChars` / `toolMaxChars` | `1400` / `8000` | 注入与工具输出的截断上限 |
| `skipPrefixes` | `["/", "!"]` | 以这些字符开头的消息不检索 |

索引与脚本都在 Harness 之外的本地目录，需要单独维护：改完卡片后用建库命令重建对应库，否则检索的还是旧内容。

## 已知局限

- **它是针检索器，不是语义检索器。** 答案措辞唯一时很准；语料里一旦出现「复述问题原话但没回答问题」的干扰块，首位命中率会明显下降。
- **依赖本地 Python 与索引。** 索引没建、Python 路径变了，两个能力都会静默失效（注入不插内容，工具返回提示字符串），不会让会话报错。
- **每次检索是起一个进程。** 自动注入会让每一步多等 1–2 秒，这是刻意的取舍：换来的是一条与本轮任务相关的经验块。
- **注入有上限。** 默认最多 1400 字，超出部分截断；需要全文时用 `rag_search` 的 `full`。
